# 검사 유효성 점검 (Phase 2b)

새 모델 출시는 검사 재검토의 계기이지 자동 만료 사유가 아니다. 검사 목적을 먼저 구분한다.

- **필수 계약·회귀 검사:** 금지 내용, 필수 섹션, 파일 무결성, 권한·프로젝트 제약. 계속 통과해도 유효하다. 위반 빈도가 낮다는 이유로 제거하지 않는다.
- **모델 비교 평가:** 모델·프롬프트 사이의 차이를 측정한다. 대표 사례가 모두 쉽게 통과하면 구분력 부족을 의심하고 현재 실패·경계 사례를 보충한다. 기존 계약 검사를 대체하지 않는다.

## 절차

1. 이번 변경과 관련 있는 검사부터 고른다. 필요한 범위만 확인하고 나머지는 미검토로 남긴다. 검사 목적·보호하는 조건·현재 대상과 최근 실행 근거를 기록한다. 이력을 못 찾은 것은 실패가 없다는 뜻이 아니다.
2. 계약 검사에는 정상 입력과 **그 검사가 탐지하도록 설계된 위반**을 넣어 기대 PASS/FAIL과 비교한다. 격리된 복사본을 사용하고 원본·실서비스에는 결함을 주입하지 않는다. 위반 입력이 PASS이면 검사 결함, 누락된 검사 범위, 시험 입력 오류를 먼저 구분한다. 이를 모델 발전에 따른 만료로 단정하지 않는다.
3. 모델 비교 평가에는 실제 작업과 관련된 일반·경계·과거 실패 사례가 포함되는지 확인한다. 모두 통과해도 표본이 쉬운 것인지 성능이 좋아진 것인지 구분한다. 출처와 판정 기준을 기록하고, 실패 가능성을 만들기 위해 무관한 난도를 추가하지 않는다.
4. 결과를 `보존 / 검사 결함 / 평가 표본 보강 / 검사 부재 / 미검증`으로 보고한다. 수동 검사는 명확한 기준과 관찰 근거가 있으면 유효하다. "좋아 보인다"만으로 합격시키지 않는다. 시험할 수 없는 항목은 이유와 함께 미검증이다.

검사 변경은 보호 조건을 유지하는 최소 수정으로 제안한다. 검사 목록을 찾지 못했으면 조사 범위에서 미발견이라고 쓰며, 프로젝트 전체에 검사가 없다고 일반화하지 않는다. 통과한 검사·변경 없는 입력을 반복 검증하지 않는다.

참고: [OpenAI 평가 설계](https://developers.openai.com/api/docs/guides/evaluation-best-practices). 실제 모델 행동 평가와 결정적 파일·보고서 검사는 서로 다른 증거다.
